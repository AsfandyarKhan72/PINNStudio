# Changelog

All notable changes to PINNStudio are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **More in-page help:** *About the network* (sizes, activations, network types, transforms), *About training* (phases, Adam then L-BFGS, learning rate decay, precision, IC pre-training), *About training points* (point kinds, distributions, extra points), *About callbacks* and *About boundary conditions* (the condition types, and loss-term vs exact conditions), closed by default like *About automatic weighting*.
- **README: the systems PINNStudio is tested on** (under Installation): each Linux, Windows and macOS version, the Python versions and where the one-command installer is tested.
- **Plot settings** (the button on the Results page, or *Settings → Plot Settings*): one dialog for how every saved figure looks, with a tab each for General (resolution, figure size, titles, fonts), Surface, Line, Animation and Loss, showing only what applies to the problem. Solve, the exported script and Restore & visualize all draw with it (Restore has a link to it), and it is saved with the problem. Before, Results and Restore each had their own copy of these settings (Restore's was not saved), the settings popped up every time the plot type changed, and the loss plot had a separate dialog.
- **Parameter convergence style** for inverse problems: the plot on the Line tab (line colour and width, a marker at each saved value, a log value axis -- moved here from the Inverse page -- and the true-value and final-value lines, each on or off with its colour and line style), the animation on the Animation tab (line colour and width, the most frames). Red, width 3 by default, the true value a black dashed line and the final value a grey dotted one. Shown whatever problem is open, since Restore draws an inverse model's plots with them too. The plots also use the resolution, and the animation the frame rate, set there.
- **More plot settings:** *Grid lines* (General tab, on by default) for the line plots and line animations, the line comparisons of Error Analysis, the loss plot and the parameter convergence plot and animation. *Reference in line comparisons* (Line tab): the reference drawn as a line, or as dots so it stays visible under the PINN's dashed line. The parameter convergence plot and animation can each be drawn as a line, a line and markers or markers only, with the marker shape (circle, square, triangle, cross) and size on the Line tab; the animation marks the current value with a dot (on by default). The older *Markers* tick box is read as *Line and markers*. Solve, the exported script and Restore all use them, and they are saved with the problem.
- **Fewer measured points without changing the files** (Inverse problem → Measured data → *Use*): all points, a coarser grid (*points per axis*: evenly spaced values along each space axis, the edges kept, each time in a file reduced the same way; 101 × 101 with 51 gives 51 × 51) or a number of random points (the run's seed, so it repeats). It applies to every measured-data file, and a line under it says what the files hold and what is kept (*101 × 101 grid, 10,201 points → 51 × 51 = 2,601 points*); a file that is not a grid gets random points instead. Both scripts do the reduction, so the exported script shows which points were used. Saved with the problem. Allen-Cahn 3D's Inverse mode now uses every second point of its 51³ grid (17,576 of 132,651 points; with each point also a training point, the full grid made the run several times slower). The large-data log note counts the points kept.
- **Sweep: a data-size study for inverse problems.** *Measured data: grid points per axis* and *Measured data: random points* can be swept, and for an inverse problem `sweep_summary.csv` now lists each run's inferred parameters and, when the true value is known, their error in percent; `sweep_error_vs_parameter.png` plots that error against the swept value above the solution error.
- **Numbers in figures follow one standard** (*Plot settings → General → Numbers*): significant digits (4 by default; inferred parameter values two more, 6), scientific notation *Automatic* (below 0.01 or from 100,000 up; errors always with a power of ten, as before), *Always* or *Never*, and the style, 1.23 × 10⁻⁴ or 1.23e-04. One helper writes every number in a figure, so times now read *t = 0.25* everywhere (some figures wrote *t = 0.2500*, others *t = 0.250*); errors in titles show 4 significant digits instead of 3. The notation also applies to axis and colorbar ticks. Solve, the exported script and Restore all use it, and it is saved with the problem. Files and the log are unchanged.
- **Parameter convergence animation on the Results page:** *Plot type → Parameter Convergence (GIF)* makes the animation after training (Solve and the exported script), as Restore could. Solve, the exported script and Restore draw it with the same code.

- **More plot settings, so less is fixed in the code:** the PINN and Reference line colours (*Line* tab), the colour map of the |Error| panels (*Surface* tab; the solution's by default), how many panels per row the error-analysis figure has (*Line* tab, 4 by default) and the resolution of saved animations (*Animation* tab, 150 DPI). Solve, the exported script and Restore all use them, and they are saved with the problem.
- **Inverse → Save parameters** takes any number of iterations (typed, e.g. *Every 250 iters*), not only the listed ones.
- **Final loss (unweighted):** the log now also gives the final loss with each term divided by its loss weight, and the sweep lists it in `sweep_summary.csv`. Bayesian search can minimise it (*Objective → Final loss (unweighted)*), so a loss-weight sweep compares runs fairly; the weighted total is smaller just because a weight is.
- **Legend font size** (*Plot settings → General*; *Automatic* keeps each figure's own, 7 to 10) and **3D grid resolution** (*Surface* tab, 40 by default): the grid of the 3D surfaces in plots, animations and Error Analysis, which was fixed at 40 (Restore's static 3D surface used half the 2D grid).
- **GPU checks** (`benchmarks/gpu_check.py`, `benchmarks/mac_gpu_check.py`): time the same three problems (Heat 1D, Poisson 2D, Heat 2D) on the CPU and the GPU, with Adam and L-BFGS, and compare the errors. The NVIDIA one also checks the PyTorch build (a CPU-only build on a PC with an NVIDIA GPU), the driver, and, while it trains, the GPU's use, clock, power, power state and PCIe link, and lists anything that looks wrong; `--watch` records the GPU while PINNStudio trains. The README's Speed section has the results: on an M1 Apple's GPU was never faster than the CPU, so a Mac keeps training on the CPU, and the installer now says so.
- **CPU threads** (*Settings → GPU / Hardware*): *Automatic* (about one per performance core, at most 8, as before) or a number of your own, for CPU training. Saved with the problem and kept when an example is loaded, like *Train on*.
- **The results folder is remembered** between sessions (the last one used, if it still exists).
- **Live loss axis:** *Plot settings → Loss → Logarithmic* now also sets the live loss plot during training, not only the saved figure.

- **Train on: CPU** (*Settings → GPU / Hardware*): trains on the CPU even when there is a GPU. A small network (a 1D problem, a few thousand points) often trains faster there, since each GPU step waits on Python more than it computes; the timing study measured 2.2× for the 1D inverse diffusion example. Both the Solve script and the exported script then hide the GPU from PyTorch. Saved with the problem.

- **Measured points as anchors, now a choice** (Inverse problem → Measured data → *Check the equation at the measured points too*): on by default, as before (each measured point is also a training point). Off keeps the points only in the data loss, which is faster with a lot of data; the anchors study (`benchmarks/anchors_study.py`) found the parameters about as accurate on most inverse examples, but not with very few points (Brinkman-Forchheimer, 5 points: 15–40 times off without them). Saved with the problem; the large-data log note and *About inverse problems* mention it. An IC file's points can also be anchors (`ic_file_anchors`, off), but the study found that no better and slower (Heat 2D 7× worse at $t = 1$), so it has no window option.

- **Platform matrix** (`.github/workflows/platform-matrix.yml`, for commits marked `[matrix]`): the tests and the window check on Ubuntu 22.04 and 24.04 (x64 and ARM), Windows Server 2022 and 2025 and Windows on ARM, macOS 14 and 15 and an Intel Mac, with Python 3.9 to 3.14; the installer on Linux, Windows (x64 and ARM) and an Intel Mac.

- **Timing study** (`benchmarks/timing_study.py`): the same examples solved as the plain exported script, as the script Solve runs, and through the window's Solve, on the CPU and on the GPU, timing the training and the whole run.
- **All-examples check** (`tools/all_examples_check.py`): every Forward and Inverse example loaded as the window loads it, validated, written out as both scripts, and trained briefly to the end.

- **Tests on Windows, macOS and Linux** on GitHub Actions (`.github/workflows/platform-tests.yml`): the test suite and `tools/smoke_gui.py`, which drives the window end to end (load a template, train it, show the results with Error analysis, Restore & Visualize every plot type) and fails on any error the window shows; failures are reported as annotations on the run (`tools/junit_annotations.py`).
- **One-command install** (`get-pinnstudio.sh` for macOS/Linux, `get-pinnstudio.ps1` for Windows): installs PINNStudio with [uv](https://docs.astral.sh/uv/), with its own Python 3.12 and the PyTorch build that matches the NVIDIA driver (`--torch-backend auto`, CPU-only without one), so Python and git do not need to be installed first. It puts `pinnstudio` on the PATH, creates the desktop shortcut and reports whether training will use the GPU; running it again updates PINNStudio. The README and the website lead with it; pip and the source install are still described. With a version that has no `--create-shortcut` (1.4.0 on PyPI), it skips the shortcut instead of opening the window.
- **Desktop shortcut:** `pinnstudio --create-shortcut` adds PINNStudio to the Start menu and desktop (Windows), `~/Applications` (macOS) or the app menu (Linux, not the Desktop, where Ubuntu blocks launchers until *Allow Launching* is chosen), with the app icon; `--remove-shortcut` removes it, including a Desktop copy made earlier. `python -m pinnstudio` starts the app. On Windows the shortcut runs `pythonw.exe`, so no console window opens, and training scripts then run with the matching `python.exe`, also without a console window.
- **Source code links in the README:** every feature now links to the code that implements it (the method in the generated script, and the GUI panel where that helps). Each feature names its functions once in a comment, and `tools/update_source_links.py` rewrites the links with the current line numbers; `tests/test_source_links.py` checks that every named function still exists.
- **Local templates:** templates you keep for yourself can go in `pinnstudio/core/local_examples.py`, with their reference data in `reference_data/local/`; both are ignored by git, and the template is added to the Examples lists when the file is there (`pinnstudio/core/pinnstudio_examples.py` says how).
- **Second 1D Allen-Cahn template**, *Allen-Cahn 1D – Wight & Zhao (whole interval)*: the same problem trained on the whole time interval in one run with the best setup of the training methods study (exact periodicity, exact initial condition, causal training with the stepped ε, MsFFN network with scales 1, 5), 0.18–0.24% error at $t = 1$ in about 3 minutes on an RTX 4090. The time-adaptive template is now listed as *Allen-Cahn 1D – Wight & Zhao (time-adaptive)*. Templates now also set causal training and the network type, and turn them off again for the next template.
- **Training methods study, 3D Allen-Cahn:** the plain setup (0.033% at $t = 1$, almost as good as the template) and exact BC + exact IC + causal + MsFFN (14%, the worst) are now run.
- **Study runner** (`benchmarks/study_runner.py`): runs the training-methods study's setups on any example, several runs sharing the GPU at once; the plans used are in `benchmarks/plans/`.
- **Exact initial conditions** (Initial conditions → *Exact (built into the network)*, per output): the output becomes IC(x) + τ·N with τ = (t − t_min)/(t_max − t_min), so it equals the initial condition at t_min whatever the network learns, and the condition needs no loss term (its row switches off). Any Scale/shift set on the Network page still applies to N. Not with time-adaptive training (each step starts from the previous step's solution) or an IC loaded from a file; validation says so.
- **Exact periodicity** (Boundary conditions → *Exact periodicity (periodic inputs)*): every axis with a periodic BC row enters the network as cos(2πx/L), sin(2πx/L) (L = the domain's length on that axis), so values and derivatives match at both ends by construction. The Network page notes when either of these builds its transform. With RBA, these two gave the lowest errors on the phase-field examples (37× on 1D Allen-Cahn without time-adaptive training).
- **Automatic weighting** section on the Loss weights page, with a short note on when to use it: per-point weights and causal training moved there from Adaptive training, which keeps RAR and time-adaptive training.
- **Causal training** (Loss weights → *Automatic weighting* → *Causal training*; Wang, Sankaran & Perdikaris, CMAME 2024): the time interval is split into chunks (*Time chunks*, 32 by default) and each chunk's residual is weighted by exp(−ε × the residual loss of all earlier chunks), so the network fits later times only once the earlier ones are fitted. By default ε follows the paper's schedule (*Raise ε step by step*): 0.01, 0.1, 1, 10, 100, moving on once every chunk weight is above 0.99 -- with one fixed ε = 1 the weights on 1D Allen-Cahn stayed at 0.98 and causal training barely acted (0.65% error at t = 1, against 0.18–0.64% with the schedule, 0.07–0.13% with the schedule and a Fourier-feature network). Untick it for a fixed ε. A note warns when it is combined with per-point weights (together they did worse than either alone). The log prints how far in time the weights have settled. The weights are held fixed during L-BFGS. It works with the Method dropdown's Time-Adaptive training (each step is its own interval) and RAR, in Solve and in the exported script.
- **Per-point weights** (Loss weights → *Automatic weighting* → *Per-point weights*): each training point's PDE residual gets its own weight, which grows where the residual stays large, such as at sharp fronts and interfaces. *Residual-based attention (RBA)* (Anagnostopoulos, Toscano, Stergiopulos & Karniadakis, CMAME 2024) updates the weights after every Adam step, w ← γw + η|r|/max|r|. *Self-adaptive (SA-PINN)* (McClenny & Braga-Neto, JCP 2023) trains them by gradient ascent on the loss the network minimizes. Only the training points are weighted, so the test loss stays the plain one. SA-PINN is the paper's method by default, whose weights only grow; *Keep the mean weight at 1* (ours, not the paper's) rescales them after every step instead -- held during L-BFGS, the paper's version was the more reliable one (1D Allen-Cahn, three seeds: 0.13–0.20% at t = 1, against 0.10–2.7%). *During L-BFGS*: *Plain loss* (default) drops the weights so L-BFGS refines the ordinary loss, or *Keep the weights* holds them, as both papers' methods do (stronger where the plain PINN struggles, but it made already-accurate problems such as 1D Burgers 2–10× worse). The log prints the weights' mean and maximum. They can be combined with causal training, Time-Adaptive training and RAR, in Solve and in the exported script.
- **Training methods study** (`benchmarks/training_methods.md`): about 140 GPU runs on 12 problems comparing scaling, causal training, gradient-norm balancing, RBA, SA-PINN, Fourier-feature networks, exact periodicity, a hard initial condition, time-adaptive training and more -- what helps, what doesn't, and on which problems.
- Training methods study: SA-PINN on the two 2D Allen-Cahn examples. With an exact initial condition it is the best of the weighting methods on Mattey & Ghosh (0.036% at t = 1, against 0.052% with RBA); on Wight & Zhao it is worse than RBA on the whole interval and fails with time-adaptive training (each window learns u = 0, because SA-PINN weights only the PDE points and outgrows the initial condition's loss term). The README guide and the per-point weights tooltip say to use SA-PINN with an exact initial condition.
- **1D Cahn-Hilliard template** (Wight & Zhao 2021): u_t = μ_xx with μ = γ₂(u³ − u) − γ₁u_xx as a second output, so no fourth derivative is needed. μ has no time derivative and so no initial condition; u and μ are periodic in value and slope. μ is only about γ₂ = 0.01 in size, so the network's μ output is scaled by 0.01 and the μ equation is divided by γ₂ -- written as is, its residual is about 100× smaller than u_t's and a plain PINN settles on a wrong solution (28–42% L₂ error in u); scaled, the same network and training reach 0.5–3%. The template also uses the best setup of the training methods study: the initial condition built into the network (u = −cos(2πx) + t·N), periodic inputs cos(πx), sin(πx) and SA-PINN per-point weights as in the paper, held during L-BFGS -- in u about 0.2% at t = 0.25 and 0.05–0.06% at t = 1 over three seeds (RBA: 0.6% and 0.12%), in μ 0.25–0.28% and 0.15–0.18%. Adam 20k + L-BFGS 20k. Templates now turn these settings (and an output scaling) off again when the next example is loaded. It comes with spectral reference data for u and μ at t = 0, 0.25, 0.5, 0.75 and 1 (`tools/make_exact_reference_data.py`), and as an inverse example, learning γ₁ and γ₂.
- **2D Cahn-Hilliard template** (Wight & Zhao 2021, §3.3): two bubbles that merge, u_t = Δμ, μ = u³ − u − ε²Δu on [−1, 1]² (periodic), ε = 0.05, t ∈ [0, 1], with μ as a second output. The paper's initial condition is a max of two tanh profiles; its corner where the bubbles touch is what drives the merging, but a network built on the exact initial condition sees no curvature in a corner, and every setup learned an almost frozen solution (16% / 30% error at t = 0.25 / 1). The template writes it as tanh((r − min(R₁, R₂))/2ε) with the min smoothed (u changes by 0.5%, along the line where the bubbles meet). With the exact initial condition, exact periodicity and SA-PINN as in the paper: 1.2% / 3.8% in u. Comes with spectral reference data for u and μ at t = 0, 0.25, 0.5, 0.75, 1 (it replaces the earlier u-only files, which agreed with it to 0.02–0.08% but used the unsmoothed initial condition).
- **1D and 2D Cahn-Hilliard templates after Mattey & Ghosh (2022)**, with reference data. 1D (eq. 25, u(x, 0) = cos(πx) − exp(−4(πx)²)): solved with time-adaptive training, 10 windows of 0.01 over the fast start and 9 of 0.1, the IC as a loss term and exact periodicity -- 0.29% error at t = 0 and 0.48% at t = 1, where every whole-domain setup failed (25–90%), as the paper's standard PINN does. 2D (IBVP-2, time rescaled t' = t/0.005, α = 0.0002, which reproduces the paper's figures; the stated 0.02 makes the pattern decay): exact IC, exact periodicity and SA-PINN, 0.20% error at t' = 1. The Time-Adaptive IC grid now also offers 201 points.
- **3D Allen-Cahn template** (Wight & Zhao 2021, §3.2): a shrinking sphere, u_t = λ(ε²Δu − u³ + u) on [0, 1]³ (periodic in x, y and z), λ = 10, ε = 0.05, t ∈ [0, 1], with exact periodicity and the initial condition as a loss term (weight 100): 0.03% error at t = 1. With the exact initial condition it was 0.7–0.8% whatever the weighting method. 3D templates can now be periodic on every axis and use the exact-initial-condition, periodic-input and per-point-weight settings, like the 1D and 2D ones.
- **3D view of 3D domains** (Geometry tab and Sketch, *View: 3D*): the whole domain as a shaded solid to rotate and zoom, with *Iso / Top / Front / Side* buttons. Only surfaces that bound the domain are drawn (a cut-out shows as a hole, the wall between two joined boxes disappears); each face is labelled F1, F2, ... and coloured by its boundary condition, with a legend, and the slice the flat views show is a translucent plane. *Show points* adds the training points: DeepXDE samples them in a background process with the Collocation Points settings (number of points, distribution), as *View domain & point distribution* does, and samples again when a setting changes -- to check that none land in a cut-out. Faces are still picked in the flat views or the face list. Built on matplotlib's 3D axes, so no new dependency.
- **Mid-plane slice figure for 3D problems**: Error Analysis on a 3D box now also saves `slice_comparison.png`, PINN, reference and error on the plane z = (the line-plot z) at each comparison time, which shows the inside of the solution that the surface plot of the box's faces can't.
- **`tools/make_phase_field_reference_data.py`**: the reference solutions for those two (Fourier pseudo-spectral; a stabilized semi-implicit step for Cahn-Hilliard, ETDRK4 for Allen-Cahn), each checked against a finer grid and a smaller time step (they agree to ~10⁻⁴ and ~10⁻⁵). Runs on the GPU when there is one. It also writes the references for the two Mattey & Ghosh Cahn-Hilliard examples (`reference_data/1D/cahn_hilliard_mattey`, `reference_data/2D/cahn_hilliard_mattey`).

- **Sketch a 2D domain** (Domain → Shape → *Sketch*): a **✏ Sketch** tab opens next to the Training Log with a grid canvas showing the x and y axes. You can draw rectangles, circles, ellipses and polygons (click the corners, then double-click, press Enter or click the first corner to close). Each new shape is added, cut out as a hole, or intersected with what is already there (*New shape*). Snapping is on by default with a 0.1 grid. Use *Select* to move or delete a shape; the wheel zooms and right-drag pans. Drawn shapes become ordinary Custom-geometry rows in the Domain panel, editing a row redraws the sketch, and the combined region is shaded. A saved configuration reopens on the Sketch (`geom_sketch`). The sketch takes most of the right panel while it is shown, and Solve switches back to the Training Log.
- **Boundary conditions from the sketch** (Sketch → *⌁ Edges → BCs*): the sketched domain's boundary is split into numbered edges E1, E2, ... -- the straight pieces of rectangles and polygons and the arcs of circles and ellipses that actually bound the domain (a hole cutting an edge splits it in two; collinear pieces merge). Click an edge, or Ctrl/Shift-click several, and press *New BC on selected* to add a Boundary Conditions row (Dirichlet, value 0) whose Where: picks those edges, then set its type and value as usual; *Add to* and *Remove from BC* change an existing row. Each edge is drawn in its BC's colour (grey: no BC yet), with a legend, and *Select edges without a BC* finds the ones left. The Where: expressions only use x, y and `np` (`np.isclose(y, 0) and 0 <= x <= 2`, `abs(np.hypot(x - 0.6, y - 0.5) - 0.25) < 3e-05`), so they work the same in the exported script, and each picks exactly one edge of the points DeepXDE samples.
- **Typed shapes in the Sketch**: a *Type:* field takes exact numbers for the current tool -- `x0, y0, x1, y1` for a rectangle, `cx, cy, r` for a circle, `cx, cy, a, b[, angle]` for an ellipse, `x,y; x,y; x,y` for a polygon (or one corner at a time) -- and Enter adds the shape.
- **Import a DXF or SVG drawing into the Sketch** (*📂 Import DXF/SVG…*): the drawing's closed outlines become shapes -- circles stay circles, ellipses ellipses, axis-aligned boxes rectangles, other outlines polygons (arcs and curves inside them become short straight pieces), and lines and arcs drawn separately are joined end to end. Outlines inside an odd number of others become holes. You choose a scale (e.g. 0.001 for mm → m) and whether the drawing replaces or adds to the sketch; what wasn't read (text, splines, outlines that don't close) is listed. For BCs, an arc drawn as many short pieces is still one edge, with a Where: on its circle.
- **3D Sketch** (3D → Domain → Shape → *Sketch*): draw boxes and spheres on an x–y, x–z or y–z view, combined by union, subtraction or intersection like the 2D shapes. The canvas shows the domain's slice at a depth you choose; a new box takes its depth range from *New box … from … to*, and a new sphere is centred on the slice. Boxes and spheres can be typed too (`x0, y0, z0, x1, y1, z1`; `cx, cy, cz, r`). *Faces → BCs* numbers the faces that bound the solid (each side of a box, each sphere surface) and gives each a Where: in x, y, z; faces seen edge-on in the slice can be clicked there, and every face is in a list beside it, coloured by its BC.
- **Results while training**: *Results → Live loss* plots the training loss as the run prints it (the total, or each loss term), with zoom and pan; a status bar under the window shows the phase, step, a progress bar, the time left and the current loss; *Results → Error analysis* lists the last run's errors per reference time with its comparison figures; and double-clicking the loss or solution figure opens it in a viewer that zooms.
- **Geometry tab**: every 2D and 3D domain set in the Geometry panel (not only a sketched one) is drawn next to the settings, with its edges or faces numbered and coloured by boundary condition. Selecting a BC node lets you click its edges in and out, as in the Sketch.
- **Start tab** (the first tab of the right panel): the window opens on a page to start a new 1D, 2D, 3D or ODE problem, open a saved one or a recent one, or load an example from a gallery grouped by dimension.
- **Script tab** (next to the Training Log): the DeepXDE script *Export script* would write for the current settings, highlighted and kept up to date as you change them, with *Copy* and *Export…*.
- **Results → History**: the runs saved in the Save-to folder (including a sweep's runs), with when they ran, their final loss and relative L₂ error. Double-clicking one shows its figures in Overview and its errors in Error analysis again. Select two or more (Ctrl/Shift-click) and press *Compare* to see their training loss against iteration and their relative L₂ error against time on one plot.
- **Quieter figure headers**: the *Save Figure* buttons above the loss, solution and training-monitor figures are now small save icons (right-click a figure to copy or save it too); the sweep's *Refresh* has a line icon, and its *Mode* list no longer widens the page.
- **Smaller touches**: the live loss names each term (PDE, BC 1, IC, ...); History keeps a sweep's runs in order and rescans the folder only when needed; a long *Where:* shows from its start; DeepXDE's backend advertisement stays out of the Training Log; picking an example from the toolbar offers to save unsaved changes first.
- **Copy and save figures and tables**: right-click a result figure (Overview, Error analysis, the training monitors, the zoomable viewer) to copy it, save it (as PNG or JPEG), open it in the viewer or show its folder; right-click the live loss or a run comparison to copy it or save it as PNG, PDF or SVG; right-click the Error analysis or History table, or use their *Copy* and *Export CSV…* buttons, to copy it (it pastes into a spreadsheet, with headers) or save it as CSV, at full precision.
- **Help on every settings page**: a **?** next to the page title (and *Help* in the node's right-click menu) opens that part of the documentation.
- **Equations typeset as you type**: under each equation box the equation is shown as mathematics (∂u/∂t, ∂²u/∂x², sin(πx), ...), and a note names anything it uses that isn't an output, a derivative of one, a coordinate, a named constant, an inverse variable or a function -- a misspelt name shows up before you press Solve.
- **Undo and redo in the Sketch** (Ctrl+Z, Ctrl+Y, or the arrow buttons), for drawing, moving, deleting, clearing and importing shapes.
- **Right-click menus on the model tree**: add, duplicate or delete a boundary condition, add a training phase, a trainable variable or a constant, start a new problem, and fold or unfold all sections of a page.
- **Files and shortcuts**: *Save* (Ctrl+S) saves to the problem's own file once it has one, and *Save As* (Ctrl+Shift+S) asks for a new name; *Problem → Open Recent* and the Start tab list the last eight problems; the title bar marks unsaved changes, and opening, starting a new problem or closing asks whether to save them. Ctrl+O opens, Ctrl+E exports the script, Ctrl+Enter or F5 solves and Shift+F5 stops.
- **Parameter Sweep summary plot**: every finished sweep saves `sweep_error_vs_parameter.png` in its folder -- the Error Analysis error (L₂, plus MSE and Max error when ticked) and the final loss of every run against the swept value (for a time-dependent problem each error is the mean over the reference times set in Error Analysis -- the sweep log, CSV and Bayesian search's L₂ objective use the same mean; before, the last reference time only) (log axes where values span 100× or more, a categorical axis for text settings; one panel per parameter for One-at-a-time, one line per value of the other parameters for All/Specified combinations; the baseline as a star). `sweep_summary.csv` gains a column per swept parameter and per ticked metric.
- **Parameter Sweep baseline option**: *Also run the current settings (baseline)* -- on by default only for One-at-a-time with 2+ parameters and Bayesian search, where the other runs are compared against it; a sweep of 3 values otherwise runs 3 times, not 4. Ticking/unticking keeps the user's choice (saved as `sweep_include_baseline` on/off).
- **Fractional equations**: `frac(u)` in an equation is the fractional operator of order α applied to output u, discretized as DeepXDE's `dde.data.FPDE`/`TimeFPDE` (Grunwald-Letnikov): in 1D the sum of the left and right Riemann-Liouville derivatives, in 2D/3D the integral over directions of the directional derivative (the fractional Laplacian up to its constant). New DeepXDE examples: fractional Poisson 1D/2D/3D, fractional diffusion, and inverse fractional Poisson 1D/2D (learning α).

New DeepXDE examples: integro-differential equation and Volterra integro-differential equation.

## [1.5.0] - 2026-10-07

### Added

- **Network Type (FNN / PFNN)**: an independent dropdown in the Neural Network panel. FNN (the existing default) is a single shared trunk; PFNN (`dde.nn.PFNN`, a genuine DeepXDE built-in) gives each output its own parallel sub-network merging only at the final layer -- useful for multi-output problems (e.g. 1D Schrödinger's real/imaginary parts) where the outputs have different scales/behavior. A single shared network-construction helper is used everywhere a network gets built (training scripts, exported scripts, all Restore/Error-Analysis script builders), so a training run and the script that later restores its checkpoint can never disagree on how the network was shaped.
- **Training Monitors**: track an arbitrary expression of the solution and its derivatives (`u`, `du_x`, `du_xx`, `du_xy`, ...) during training, logged alongside the loss curve, instead of only being able to inspect a quantity after training finishes. Built on DeepXDE's own `dde.callbacks.OperatorPredictor`; reuses the Custom PDE editor's own derivative-vocabulary builder, so monitor expressions use the identical `d<output>_<vars>` syntax.
- **Derivative-aware "Custom..." plotting**: the Custom expression field (previously algebraic combinations of raw outputs only, e.g. `sqrt(u**2+v**2)`) can now also reference derivatives (`du_x`, `du_xx`, ...), evaluated through DeepXDE's own `dde.Model.predict(x, operator=...)` built-in -- the same mechanism Training Monitors uses, and the same derivative-vocabulary builder, reused rather than duplicated. ## [0.1.0] - 2026-08-27

### Added

Initial public release. PINNStudio is a no-code PyQt6 GUI for building, training, and visualizing Physics-Informed Neural Networks on top of DeepXDE.

- 1D `(x, t)` and 2D `(x, y, t)` problem definitions, forward and inverse.
- Free-form PDE residual editor supporting multi-output, coupled PDE systems.
- Per-side, per-output boundary condition configuration (Dirichlet, Neumann, Periodic) and initial conditions from an expression or a data file.
- Collocation point controls (domain/boundary/initial/test counts, point distribution) with a 2D domain preview.
- Neural network configuration (hidden layers, neurons per layer, activation).
- Two-stage optimization (Adam + L-BFGS) with detailed L-BFGS settings and configurable float precision.
- Multi-phase optimizer scheduling and optional IC-guided pre-training.
- Residual-based adaptive refinement (RAR) and time-adaptive stepping with transfer learning between time windows.
- Parametric studies over a chosen parameter.
- Inverse-problem support for estimating unknown PDE parameters from observation data.
- Seven built-in Quick Example templates: 1D Heat, 1D Allen-Cahn, 1D Cahn-Hilliard, 2D Heat, 2D Allen-Cahn (Mattey & Wight forms), and 2D Cahn-Hilliard (Wight).
- Bundled FEM reference data (`reference_data/`) for these templates, so Error Analysis auto-configures against real ground truth out of the box on any machine.
- Error analysis against reference/ground-truth data (L2, MSE, max error; line and surface comparison plots).
- Configurable result plotting (colormap, resolution, DPI, colorbar, snapshot count) and solution data export.
- Live training log streaming with a Stop control.
- Model restore: reload a saved checkpoint to regenerate plots and re-run error analysis without retraining.
